# 学習ノート / Learning Notes

## 学習の進め方（4ステップサイクル）

```
 ①検出する Detect → ②理解する Understand → ③修正する Fix → ④再スキャン Verify
        ↑__________________________________________________|
```

1. **検出する**: スキャナーを実行して問題を見つける
2. **理解する**: `docs/vulnerabilities/` の解説を読み、「なぜ起こるのか」を図で理解する
3. **修正する**: アプリ側の設定・コードを直す（これが一番の学び！）
4. **確認する**: 再スキャンして検出が消えることを確かめ、レポートに記録する

## OWASP Top 10 チェックリスト（学習用）

自分の練習アプリについて、各項目を「説明できるか」自己チェックしましょう。
（本スキャナーが自動で確認するのは ★ の項目です）

| # | カテゴリ | 一言でいうと | 確認できた？ |
|---|---|---|---|
| A01 | Broken Access Control | 他人のデータが見えてしまう | ☐ |
| A02 | Cryptographic Failures ★ | 通信やデータが暗号化されていない | ☐ |
| A03 | Injection ★(予防知識) | 入力がそのまま命令として実行される | ☐ |
| A04 | Insecure Design | 設計段階から安全でない | ☐ |
| A05 | Security Misconfiguration ★ | 設定ミス（ヘッダー・デバッグ等） | ☐ |
| A06 | Vulnerable Components | 古いライブラリの脆弱性 | ☐ |
| A07 | Auth Failures ★(Cookie) | 認証・セッション管理の不備 | ☐ |
| A08 | Software/Data Integrity | 更新プログラム等の改ざん | ☐ |
| A09 | Logging Failures | ログがなく攻撃に気づけない | ☐ |
| A10 | SSRF | サーバーに勝手な通信をさせられる | ☐ |

参考: https://owasp.org/Top10/ja/

## レポートの書き方（説明力トレーニング）

発見1件につき、次の4点を自分の言葉で書けるようにする:

1. **影響 Impact** — 放置すると何が起きる？
2. **原因 Cause** — どんな設定・コードが原因？
3. **修正 Fix** — 具体的に何を変えた？
4. **再発防止 Prevention** — 今後どうやって防ぐ？（CI・レビュー等）

## やってはいけないこと / Rules

- ❌ 他人のサイト・サーバーへのスキャン（**違法です**）
- ❌ 練習アプリのポートを外部に公開
- ❌ レポートにパスワード・トークン・個人情報を載せる
- ✅ 学んだことを「説明する」練習をする（防御者の視点！）
